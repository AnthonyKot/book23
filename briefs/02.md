# Brief — Chapter 2, "One Key for Every Door" (API2 broken authentication)

Draft: `chapters/02-one-key-for-every-door.md` (exploratory; not approved). Written 2026-09-23.
Built 2026-09-24: `NewChapter2App`, paired exercise and expiry tests, and exact marked excerpts.

## Mechanism and class fit

BrewDog's Android app shipped one bearer token, identical in every installation, as the only
credential on three API endpoints; the customer was selected by an ID appended to the URL, so
anyone holding the app's token could read any customer's PII. Fits API2 (broken authentication):
the server verified a credential that identified the *app*, not the *person*, so every later
authorization decision had no verified identity to work with.

Primary source: Alan Monie, Pen Test Partners, 8 Oct 2021,
https://www.pentestpartners.com/security-blog/free-brewdog-beer-with-a-side-order-of-shareholder-pii/
(fetched and read; Domoney case 3 is only the pointer).

## Handlers / middleware needed in `service/`

- `currentUser` vulnerable: bearer token lookup; if token == app key, `user = X-User` header
  (trusted). Excerpt `ch02-vulnerable`.
- `currentUser` fixed: bearer token → session store → `session.User`; app key alone → 401 on
  `/v1` (v1 shares the session middleware); `X-User` ignored everywhere. Excerpt `ch02-fixed`.
- Session store with issue time; fake clock so a 13-hour-old token expires (12-hour lifetime).
- Login route to issue session tokens (minimal, fixture credentials; do not present as production auth).
- Fixed mode keeps ch. 1's loader; ch. 2 adds only identity.
